# An Unexpected Snag💂‍♂️

As I worked on the site, I ran into a problem: emojis. All the trendy blogs and articles these days seemed to use them, but React would not let me insert emojis directly.

- An example that produces a console error

  ```html
  <p>EMOJI😀</p>
  ```

- The correct way

  ```html
  <p>EMOJI<span role="img" aria-label="smile">😀</span></p>
  ```

I am not entirely sure why. My guess is that this precaution is necessary because emojis may not render correctly in some browsers. (Interestingly, emojis cannot be inserted only in the body text—the `<p>` tag—while they work just fine in other tags such as `<h1>` without any special handling. Hmm...)

The best solution I found online was to [create a separate Emoji tag.](https://medium.com/@seanmcp/%EF%B8%8F-how-to-use-emojis-in-react-d23bbf608bf7) This works fine when you write a page by directly editing the Component yourself, but it is extremely cumbersome when converting Markdown to JSX. You would have to add an `<Emoji>` tag every time you write Markdown.

Of course, since [a regex for detecting emojis](https://stackoverflow.com/questions/24840667/what-is-the-regex-to-extract-all-the-emojis-from-a-string) already exists, I simply wrote a function that wraps every emoji in `<Emoji>`, applied it to the Markdown, and then converted the result to HTML.

# Second Error - Escaping🏃‍♀️🏃‍♂️

The one place where this approach did not work was code blocks. When writing code, you may sometimes put an emoji inside a code block. Even the opening section of this post contains an emoji inside one. If you perform the replacement directly in the Markdown in a case like this, the Emoji tag ends up inside the code block.

```html
👉a string like this
```

```jsx
<Emoji>👉</Emoji>a string like this //becomes this.
```

But the [converter](https://www.npmjs.com/package/showdown) that turns Markdown into HTML naturally recognizes this as part of the code and escapes the emoji tag during conversion, so the tag itself ends up visible in the result.

The solution I found, then, was to replace the emojis after converting the Markdown to HTML.(...)

# Third Error - Image

At this point, emojis seemed to be working properly in the posts. Admittedly, the raw tags showed up when I generated the TOC, but I simply stripped them all out with a regex replace.

But when I tried to add an image to a post, the image would not load either. The problem lay in the way the JSX file was generated. This is no longer how it works, but previously I converted the Markdown file to HTML and had a functional component return the entire thing as-is.(....)

```js
const html = converter.makeHtml(markdown);
const jsx = `import React from 'react';export default function(props){return(<React.Fragment>${html}</React.Fragment>);};`;
// Save the jsx to a file
```

That means image tags are inserted in the same way as the rest of the HTML.

```jsx
function Component(){
    return(
        // Some jsx~~~
        <img src="./image.jpg"></img>
        // Some jsx~~~
    );
}
```

React uses webpack when building, and webpack does not specially parse the `src` attribute of an `img` tag. As a result, the `src` attribute of the `img` tag generated by the build points to the image using a path relative to the JSX file. Because that path does not exist inside the build folder, the server cannot provide the image when the web browser requests it.

The correct way to specify a relative path in an `img` tag is to use `require`, as shown below.

```jsx
<img src={require("./image.jpg")}></img>
```

Then webpack recognizes that an external resource is being loaded and automatically includes the image in the build directory when bundling.

I solved this problem as well by replacing every `src` attribute in the image tags.

# Fourth Error - Tag Style

But then another error appeared. It was caused by a subtle difference in tag syntax between HTML and JSX. In HTML, you close an `<img>` tag with just an angle bracket (`<img>`). In JSX, however, you must include a slash (`<img/>`).

By this point, I had a strong feeling that every future addition would cause yet another error like this. So instead of embedding the HTML directly into a string when converting it to JSX, I decided to use a proper library. After converting the Markdown to HTML, I used the library to convert it once more into a JSX file.

# Fifth Error - Emoji Again

I used the [htmltojsx library](https://www.npmjs.com/package/htmltojsx) to convert HTML to JSX. But yet another problem arose: when it converted an `<Emoji>` tag, it turned into `<emoji>`. In other words, every tag was converted to lowercase. Presumably, because all HTML tags are lowercase, the developer used a `toLowercase` function during parsing to make the tag names consistent.

So I gave up on the `<Emoji>` tag and decided to insert the full, lengthy HTML tag directly: `<span role="img" aria-label="smile">😀</span>`.

# Final Result

In the end, the process for converting Markdown to JSX was as follows:

1. Convert the Markdown to HTML using the `showdown` library.
2. Wrap the emojis in the converted HTML with `<span>` tags.
3. Convert it to a JSX file using the `html2jsx` library.
4. Change the `src` attributes of the `<img>` tags to use `require`.

And so, after this long and arduous bout of trial and error, I finally completed the blog post system.
