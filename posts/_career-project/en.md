### Java

- [x] Difference between == and equals
  - In Java, the former compares memory addresses. The latter compares actual values rather than object addresses. How the comparison is performed depends on the class's implementation of Equals. Therefore, the former is logically transitive, while the latter may not be. In other words, a.equals(b) and b.equals(c) may be true while a.equals(c) is false.
  - Primitives can be compared with the == operator because, in Java, all constants go into the Runtime Constant Pool, and variable declarations on the Stack hold addresses into that Runtime Constant Pool.
    - But would that mean that values produced by calculations cannot be compared with ==?
- [x] Differences among Array, LinkedList, and ArrayList
  - Array
    - Physical addresses and logical addresses are identical.
    - Therefore, the index operator can be used.
    - Its time complexity is O(1).
    - The memory space is contiguous.
    - It is supported through programming-language syntax.
    - Its size is fixed.
  - List
    - A data structure in the Collection Framework representing an ordered collection of data. Its storage size is variable rather than fixed, and gaps in the middle are not allowed.
  - ArrayList
    - A data structure that internally stores data using an Array.
    - It overcomes the limitation of an array's static size.
    - In theory, physical and logical space are identical, but because it wraps an array, the index operator cannot be used directly.
    - When the array grows, it internally creates a new array and copies the data.
    - Therefore, its time complexity is the same as an array's.
  - LinkedList
    - An implementation of a doubly linked list.
    - Therefore, its memory space is noncontiguous.
    - Its time complexity follows that of a linked list.
- [x] Difference between call by value and call by reference
  - With call by value, the parameter is copied when a function is called. With call by reference, only a reference to the value is copied.
- [x] Does Java use call by value or call by reference?
  - Primitives are called by value, and Objects by reference.
- [x] Differences among DAO, DTO, and VO
  - DAO (Data Access Object)
    - Directly accesses the DB and performs CRUD.
    - Connects the Service and the DB.
    - Repository package.
  - DTO (Data Transfer Object)
    - An object for exchanging data between layers.
    - Does not have getter/setter logic.
    - Used to send data obtained from the DB to a Service, Controller, and so on.
  - VO (Value Object)
    - A literal-like concept representing the value itself.
    - Objects with all the same attributes are treated as the same object.
    - Immutable.
    - May have logic other than getters/setters.
- [x] Difference between equals() and hashCode()
  - hashCode
    - Returns an integer that identifies an object.
    - Different hashCodes mean different objects, but equal hashCodes do not guarantee that the objects are the same.
  - equals
    - Compares using hashCode and, when the values match, directly compares the properties.
  - Because equals uses hashCode internally, equals and hashCode must always be implemented together. Implementing only one can cause behavior different from what was intended.

### FE

- [x] What is the event loop?
  - JavaScript's event-loop system consists of the following elements:
    - Call stack
    - Task Queue
    - Microtask Queue
    - Heap(for variables)
  - It operates in the following order:
    1. Execute the call stack.
    2. If an asynchronous Promise operation occurs during execution, put it into the Microtask Queue.
    3. If an asynchronous operation that is not a Promise occurs, put it into the Task Queue.
    4. When the call stack becomes empty, pop one item from the Microtask Queue and put it onto the Call stack.
    5. When both the call stack and the Microtask queue are empty, pop one item from the Task queue and put it onto the call stack.
- [x] Execution timing of setTimeout(…, 0)
  - According to the event loop behavior above, it executes after the synchronous call stack is empty and all microtasks have run.
- [x] What is event delegation?
  - When the same event must be attached to many elements with a common ancestor, event delegation handles and controls the events at the ancestor instead of attaching an event directly to each element.
  - This is possible because HTML events operate through capturing / bubbling.
    - Capturing: the event propagates from an ancestor to a descendant (rarely used)
    - Bubbling: the event propagates back from a descendant to an ancestor
- [x] What is a first-class function?
  - A programming language is said to have First-class functions when functions in that language are treated like any other variable.
  - To summarize, If a function can be treated like a variable, it it first-class function.
- [x] What is hoisting?
  - Declaring variables before executing a function/global scope.
  - Hoisting occurs for functions and variables declared with var, but not for const or let. (temporal dead zones)
- [x] What is a closure?
  - Accessing variables from a function's inner scope (lexical scope) outside the function after it returns.
  - Usually used in the form of a higher-order function, although an object-based implementation is not impossible.
- [x] Explain the distinction between cookies and sessions

    - Sent along with requests to the server

  - Session:

- Difference between undefined and null

- [x] What is this?
  - In JavaScript, the this keyword refers to an object. Which object depends on how this is being invoked (used or called). The this keyword refers to different objects depending on how it is used:
    - In an object method, this refers to the object.
    - Alone, this refers to the global object.
    - In a function, this refers to the global object.
    - In a function, in strict mode, this is undefined.
    - In an event, this refers to the element that received the event.
    - Methods like call(), apply(), and bind() can refer this to any object.
  - What is bind?
    - Bind takes a method to another method.
    - Usually used to preserve `this` keyword.
- [x] What are prototypes and prototype chaining?
  - Prototypes are the mechanism by which JavaScript objects inherit features from one another.
  - Prototype itself is also an object, so that it has its own prototype.
  - This is called _prototype chain_ and it ends when prototype is `null`
  - When property of an object is referenced,
    - Runtime looks for property of object itself
    - If can't find it there, looks in the prototype object
      - Do this recursively.
- [x] What is the Semantic Web?
  - Literally, a semantic web. Rather than assigning HTML tags only visual functions, it makes it possible to analyze the meaning carried by those tags as well.
  - Good examples of the Semantic Web are header, footer, and nav. (button and a probably qualify as well.)
  - An example contrary to the Semantic Web is implementing every tag as a div.
- [x] Difference between Unknown and Any
  - Semantically, both mean unknown type but act differently.
  - `unknown` is a type-safe counterpart of `any`.
    - Variable of `any` type can assign any type and be assigned to any type.
    - Variable of `unknown` type cannot assign any type and cannot be assigned to any type.

### Others

- [ ] How HTTP/2 works
  - Based on the SPDY protocol developed by Google
  - Performance improvements over HTTP/1.1
    - Multiplexing
      - Stream: Bidirectional stream of bytes that can carry more than one message
      - Message: Sequence of frames
      - Frame: Minimum communication unit
      - Multiple stream on single TCP connection
    - Header compression
    - Prioritization
    - Protocol negotiation
    - TLS 1.2+
    - Resolves head-of-line blocking problem, partially, because TCP does not consider multiplexing of higher layer. Single loss packet at one stream will block all messages.
- [ ] How HTTP/3 works
  - QUIC over UDP
  - QUIC includes TLS 1.3
  - Resolves head-of-line blocking problem
- [ ] What is Diffie–Hellman key exchange?
  - For generator $G$ of multiplicative group of order $P$ ($G$, $P$ is public), Alice and Bob select secret $a, b$ and exchange $G^a$ and $G^b$.
  - Because there are no known method for calculating discrete logarithm, for large enough $P$, $a, b$ cannot be calculated.
  - Then use $(G^a)^n=(G^b)^a$ as symmetric private key.

    - Level 3

      - Redundancy—generally enables availability up to 99.98%
    - Level 4
      - Disaster recovery system
      - Automatic recovery from disasters == failover

- [x] Three types of database integrity
  - Entity Integrity
    - Table must have primary key
    - Primary key must be non-nullable unique
  - Referential Integrity
    - Foreign Key must be null or valid primary key of referenced relation
    - There must be an entity in referenced table for every foreign key
  - Domain Integrity
    - Value of entity should meet its constraint
  - Null integrity
    - A condition that some property of a table cannot be null.
  - Unique integrity
    - A condition that some property of a table should be unique in that table.
  - Key integrity
    - A table must have at least one key
- [x] Characteristics of a relational DBMS

  - Contrast to NoSQL - Schema-less DBMS, They have schema and all fields are (by definition) cannot be nested, and should not be nested.
  - Table represent 'Relation' of elements in domains

- [x] What interesting new database technologies are there these days?
  - Broadly speaking, NoSQL systems such as Redis and MongoDB have emerged within the DBMS ecosystem itself.
  - On a smaller scale, various DBMSs seem to be emerging.
  - Looking beyond DBMSs to the repository layer of a three-tier architecture, new forms of ORM such as TypeORM and Prisma are emerging.
